## 1. 已定案：照這些做

產品方向（每條一句，細節見 HTML 版）：

1. **多人核心：痕跡為底、同在為峰。**世界不依賴任何人在線；同一套同步有兩種速度，一起在線時即時，分開時晚點。
2. **見證的內容屬於世界，大家共享。**先走到的人寫下開始；後來的人同步，不重新生成。個人進度留在存檔。
3. **新世界預設「朋友圈、邀請制」**，可改成私人或公開。
4. **很久沒人去的地方回到霧裡，等人重新見證。**歷史不刪，舊樣子成為傳說。
5. **設計重心是舒適與照顧。**預設玩法是探索；戰鬥是選配，而且一定有安全的家與城鎮。
6. **收斂成一套 2D。**地點改用 engine2d；AI Worlds 成為世界裡的「異界」地點；R3F／Rapier 凍結，只維持可讀。
7. **手機：先讓架構不擋路。**素材依雜湊按需下載、離線優先、AI 經平台代管、輸入走動作表。
8. **世界有節拍**（合併、照顧與遺忘、換季），並由 AI 寫傳聞；傳聞只轉述歷史中真的發生過的事。
9. **AI 費用照沉浸式翻譯的模式：**先給每位玩家固定額度，之後自帶金鑰或訂閱；本機模型也要能用。
10. **影像現階段不商用**，可以用 Qwen-Image-2.1。素材生成必須接在可替換的介面後面，因為訂閱一上線就算商用。
11. **上鏈等共享世界穩定再做**：只做創世出處與每拍指紋，玩家不需要錢包。現有合約不部署、不擴充。

Rev 6 新增的六條底線：

- 走路不等 AI；互動當下不呼叫模型。
- AI 只提案：通過 parser 與規則驗證、經確認（或依世界規則自動確認）後，才寫進歷史。
- 同一份驗證兩邊跑：見證、地點、章節的驗證寫成 `src/shared`／`src/dsl` 的純函式，客戶端與世界服務共用。
- 歷史只累積；「現在的樣子」由歷史推導。
- 物理有版本：影響世界長相的程式（地形、戰鬥公式、lore 常數）改了就升版本。
- 鏈可以整個關掉，每個畫面照常運作。

## 2. 名詞

同一個詞在程式、文件、prompt 裡都用同一個意思。

- **創世**：世界不可變的起點（聖經、規則、種子、故事骨架、風格參考圖、物理版本）。今天的卡帶（`src/shared/cartridge.ts`）就是它的雛形。
- **共同歷史**：同一個世界所有人共享、只增的紀錄。今天散在存檔裡：`chunks/`、`lore.jsonl`、`notes.jsonl`、`karma.jsonl`、`land.storyMore`、`land.places`。
- **個人進度**：只屬於一位玩家（`save.json` 的位置、背包、委託與章節進度）。
- **見證**：第一次走進未記之處時，AI 起草、驗證並確認後寫進共同歷史（今天是 `narrative/witness.ts`、`app/land/witness.ts`）。
- **痕跡**：留給後來的人看的東西，包括見證的地方、手記、路標、禮物。
- **同在**：同時在線看得見彼此。屬於暫時資料（awareness），不進歷史。
- **提案**：AI 產出在確認前的狀態。
- **異聞**：同一處兩份寫法中沒被採用的那份，保留並列。
- **節拍**：世界服務定期執行的一拍。
- **異界**：入口後面是沙箱 AI 小遊戲的地點（今天的 AI Worlds，Rule 12）。

## 3. 目前階段：第一段「修好已經設計好的」

這一段不改資料格式，也不加新玩法，只把設計好卻沒接上的東西接起來。照順序做；每項做完就回報，除非你一次被指派多項。每項的「完成」都必須能用測試或實機觀察確認。

### 3.1 掛上世界 harness，讓 lore 熱區進 prompt
- 現況：`useWorldHarness`（`src/renderer/harness/useWorldHarness.ts`）沒有呼叫者，所以 `mountWorldHarness` 從未執行，`src/renderer/narrative/turn.ts:65` 的 `getWorldHarness()` 永遠是 null。世界快照、lore 熱區（`src/harness/builtins/worldContext.ts`）和 mod 段落都沒進 prompt。
- 做：在 Play 載入世界時掛上世界 harness，離開時卸載。
- 完成：見證、章節、地點的 prompt 都包含 lore 熱區與世界快照，有測試斷言組出的 sections 裡有它。

### 3.2 每次 AI 呼叫都記用量並顯示
- 現況：`src/renderer/narrative/pipeline.ts:61` 回傳 `usage: null`；只有 AI Worlds 有記錄；沒讀 `cached_tokens`。
- 做：每個呼叫點（文字與圖片）都記下用途、模型、輸入、輸出、快取輸入、毫秒，依世界累計，並用一個畫面顯示。
- 完成：沒有任何呼叫點回傳 null 用量；畫面上看得到本世界的累計；有測試。

### 3.3 取消時真的中斷請求
- 現況：`src/harness/turn.ts` 呼叫 `input.chat()` 時沒傳 signal，只在步驟之間檢查；`narrative/program.ts`、`pipeline.ts` 沒有 signal。盤點也指出 AI Worlds 工作坊的圖片取消沒接上，動手前先確認。
- 做：把 `AbortSignal` 從畫面一路傳到 `chat()` 和圖片請求。
- 完成：見證、章節、圖片生成中途取消時，main 的 log 顯示請求中止；結果不被套用，可玩版本不變。

### 3.4 串流畫到畫面上
- 現況：`onDelta` 只在 narrative 內部傳遞，沒有畫面使用。
- 做：至少讓 Create 的計畫步驟與章節卡逐步顯示文字。
- 完成：實機看得到文字逐步出現。

### 3.5 風格不寫死
- 現況：昭和氣氛寫在 `src/dsl/prompts/newWorld.ts:37`（起點場景限制在 54–56 行）；鄉間道具寫在 `src/dsl/prompts/chunk.ts:56`；圖片固定 16-bit，在 `src/main/works/images.ts:23`。
- 做：把這些搬進內建世界自己的聖經與風格（`src/main/game/aether-land.json`，由 `scripts/build-base-game.mjs` 產生，照卡帶規則發新版本，舊存檔釘在舊版）。prompt 與圖片改成讀世界自己的設定；道具清單由世界風格決定。
- 完成：用非鄉間的點子（例如「沙漠裡的鐘錶城」）建世界，聖經、起點與見證都沒有昭和元素；內建世界的感覺不變。

### 3.6 起點場景有雲端路徑
- 現況：`src/main/inference/ipc.ts:76` 只註冊 `appleLocalProvider`，沒有 Apple 本機模型時，Create 建造會失敗。
- 做：Apple 本機模型不可用時，改用已設定的聊天模型寫起點 Scene DSL，沿用既有的 prompt、parse、repair 與 `originIssues` 檢查。
- 完成：沒有 `/usr/bin/fm`、只有 OpenAI key 的環境也能完成 Create 並進入遊戲。

### 3.7 備份包含整個世界
- 現況：`src/main/instances/backup.ts` 只打包 `instance.json`、`save.json`、`karma.jsonl`。
- 做：加入 `chunks/`、`lore.jsonl`、`notes.jsonl`，匯入時同樣驗證；舊格式仍可匯入。
- 完成：匯出 → 刪除 → 匯入之後，見證過的土地、lore、手記都在（測試加實機）。

### 3.8 卡帶匯入保留聖經、故事與對白
- 現況（讀程式推論）：`src/main/cartridges/ipc.ts:62` 重新發布時只帶 manifest、rules、scenes、assets。
- 做：先寫匯出 → 匯入的來回測試重現問題，再修。
- 完成：同一張卡帶匯出再匯入，內容雜湊相同。

### 3.9 2D 大地畫出其他玩家
- 現況（讀程式推論）：`RemotePlayers` 只掛在 3D 的 `src/renderer/engine/GameCanvas.tsx:218`；engine2d 與 hd2d 都沒讀遠端位置。
- 做：在 `LandView2D` 的兩種畫法中畫出遠端玩家（名字與朝向即可）。
- 完成：兩個行程在同一個房間時，兩種畫法都看得到對方移動。

### 3.10 驗證通過前不同步土地
- 現況（讀程式推論）：`src/renderer/net/landSync.ts` 的 `useLandSync` 一有房間就開始發布與鏡像，不等 `SessionHello`。
- 做：只在對方驗證通過後，才發布或接收土地、lore、手記、家。
- 完成：有測試證明未驗證的一方收不到任何土地資料。

### 3.11 物理版本
- 現況：地形（`src/shared/chunks.ts`）和戰鬥公式（`src/shared/combat.ts`、`progression.ts`）不在任何雜湊內；`ENGINE_API_VERSION` 是 1。
- 做：定義物理版本號並寫進世界的釘選（runtime pin）；加一個「地形指紋」測試。
- 完成：改了地形產生或戰鬥公式卻沒升版本時，測試會失敗。

## 4. 之後的階段：只看方向

現在只做第 3 節。以下是方向：做第 3 節時如果遇到會影響它們的選擇（資料放哪、介面長什麼樣），選讓它們更容易的那一邊，並在回報中說明。

- **二、創世、操作、收斂**：設定卡擴寫（逐張改、只重寫一張、鎖定）→ 低畫質概念圖選風格（之後生成都拿它當參考圖）→ 確認時報價 → 先寫起點就讓人進去；動作表與手把、選單焦點導覽；標題收成「繼續、世界、創造世界、設定」；地點改用 engine2d；AI Worlds 成為異界。
- **三、大家的世界**：先在本機把散落的紀錄收成只增的共同歷史（附遷移），再加上世界服務：中繼、世界的門、同在、痕跡、節拍。生成前先向世界確認「這裡有人寫過嗎」。
- **四、開放與長久**：帳號、額度、自帶金鑰、訂閱；訂閱前換成可商用的影像模型；世界整份匯出與重新架設；輕量上鏈；手機。
