01 · Core value

框架以「AI 更好產」為第一優先

同一個需求，選擇能讓模型用更少上下文、更少錯誤與更少修補，產出可玩結果的表示方式。

更容易生成

優先使用模型能直接產出的文字、圖片、布局與互動程式。簡單需求不必先解決 3D 座標、碰撞與相機。

更便宜地修改

換角色圖、改勝利條件或調整畫面，都能定位到小範圍內容；保留沒有要求改動的部分。

更快發現與修補錯誤

生成後直接預覽，收集可定位的錯誤，有限次修補。隨時保留上一個可執行版本。

價值順序：先證明框架降低製作成本，再讓創作者透過低成本試錯改善遊戲。作品是否有趣需要試玩，但不把完成一款大型遊戲當成框架第一階段的前置條件。

02 · Scope

2D 優先，呈現方式跟著需求走

「任意玩法」代表不必先新增專用底層模組；不代表第一版支援所有大型遊戲、任意依賴或無限制的系統權限。

面向新版決策第一版界線
呈現HTML／CSS、文字與圖片為預設；Canvas 按需使用Three.js 可選；3D、物理與世界地形都不是必經路徑
玩法模型產生具體互動、狀態與規則先用小型作品驗證自由度，不要求涵蓋每個 genre
模組提供通用服務與可重用素材不先做玩法目錄；新玩法原則上只改作品
創作一句需求 → 生成 → 試玩 → 自然語言修改不強制 Genre Matrix、Capability Compiler 或六步 Create
圖片與元素素材引用與程式分離，可獨立替換先用實際提供的素材或明確設計的 CSS 圖形；圖片生成不是起跑依賴
暫緩商店、鏈上經濟、大型編輯器（多人房間已有：Join 與家門）AFM／PCC 專項優化依量測需求排程，不綁定單一 provider

03 · Creation loop

先玩到，再用一句話改掉

下列是流程示意；實機畫面見第 02 頁「遊戲現況」。玩法摘要由模型提出，不再要求使用者先填工程表單。

01 · DESCRIBE一句話描述想做的體驗
02 · GENERATE模型產生畫面、規則與素材引用
03 · PLAY在同一個播放器直接試玩
04 · REFINE提出修改，查看結果與差異
05 · KEEP保存可玩版本，隨時回復

生成時

顯示真實進度，可取消；素材未完成就顯示缺少項目。模型不可用時提供原因，不以預製作品冒充生成結果。

修改時

規則、布局、文字與素材可分別修改。修補在草稿中完成，不覆蓋正式作品；存檔不相容時明示需重開或遷移。

何時加入框架：某件事反覆生成、容易出錯，而且由框架處理不會限制創作時，再抽成共用服務。例如素材載入與存檔；具體遊戲規則留在作品。

04 · Evaluation

用實測比較生成成本

以下是量測定義，沒有填入尚未跑出的成功率或速度承諾。以相同題目、模型設定與環境比較，保留失敗樣本。

指標如何量測
首次可玩成功率第一次輸出、未修補前，能完成題目指定的核心操作之件數／全部嘗試件數；不是只檢查載入成功
生成時間與成本需求提交至首次可操作的時間；分列模型、素材、驗證／修補耗時及可取得的 tokens／實際費用
修改成功率修改要求達成，且列出的既有行為仍正常之件數／全部修改嘗試；依改規則、換素材、調畫面分組
修補負擔首次錯誤、修補次數、變更檔案與範圍；超出上限的失敗仍計入
框架耦合新增玩法需要修改播放器或增加專用模組的次數；三個原型應共用同一播放器
模型理解成本注入的契約說明長度、必要宿主 API 數量與契約誤用；不為追求數字壓縮到難以理解
比較原則：可使用現有 DSL 路徑支援的重疊題目做基準，不強迫它執行不支援的玩法。沒有模型就標示未量測，不以手寫原型推論模型生成成功率。

01 · Title & Create a game

標題畫面就是大地本身；自己的遊戲三步做好

選單後面不是一張背景圖，是同一個 HD-2D 畫面層即時畫出來的地形。選單是 Continue、New Game（輸入或擲一個 8 碼種子，同一個種子就是同一片大地，不需要模型）、Create a game、AI Worlds、Join、Cartridges、System。Create a game 分三步：寫下世界與玩法 → 看模型提出的計畫並修改 → 建立並進入。

02 · Open land & story

走到哪，世界寫到哪；故事是地上的門

大地沒有邊：地形從種子算出來，只有第一次走進的區塊才請模型「見證」。故事章節是地上的門：每過完一章，走向下一道門的路上，背景就把下一章寫好。

無限大地

32×32 格一個區塊，只畫鏡頭看得到的區塊。河上每個區塊中心都有淺灘，所以任何門、任何地點都走得到；起點區塊永遠是乾的。

見證

第一次走進一個區塊，模型寫下它的名字、居民、對話與習俗，存進這個存檔。重複宣告世界已經記得的傳說，會併進原本的節點，不再讓整塊失敗。

無限章節，在遊戲裡玩

門的位置由宿主決定，依序開啟。背景寫好下一章：1–3 個人和他們的話、1–3 個寶物、2–5 隻怪（沒有戰鬥的世界就沒有怪），走到門口時它們已經站在門的周圍。卡帶的章節過完後，大地自己續寫，最多 99 章。

03 · Combat & tweaks

一套戰鬥，一句話加機制

大地、橫向捲軸與地城共用同一個戰鬥迴圈。「調整機制」用一句話加武器、怪物或隊伍：卡帶缺什麼模組就補什麼，只有引擎本身沒有的模組才會拒絕。

一套戰鬥模型

開火、命中、回合都走同一個迴圈。大地上的野怪由種子決定：種類看地形，等級看離家多遠（最高 30）；起點與章節的怪則是寫出來的。打倒的野怪在這次遊玩裡不會再冒出來（還沒寫進存檔）。

調整機制缺什麼補什麼

需求 → 模型提出變更 → 先試玩 → 發布成新版本。卡帶沒有戰鬥時，「加一把槍」會連戰鬥模組一起補上（玩家 100 HP、怪物 30 HP + 每級 10），而不是回一個錯誤。

04 · Places

橫向捲軸與地城，從大地走進去

地點屬於這個存檔，不產生新版本。模型只寫裡面住了誰、有什麼、要做什麼；地形由宿主從種子蓋出來，所以一定走得通，每次讀檔都一樣。

種類宿主蓋的模型寫的
橫向捲軸一條 61 格長的路，平台高差都跳得上去，偶爾一道矮牆，終點在最右邊名字、光、居民、寶箱、怪物、一個任務
地城19×19 第一人稱迷宮，有保證路線；轉身就是回大地的出口，終點在某個角落同上，再加走廊擺設
進出入口在淺灘交叉口；↩ 回到入口旁，✓ 走出終點算通過，寫一筆見證並在地圖上打勾不寫座標：模型給的位置一律由宿主重新擺到空地上
關於這些圖：全部是 2026-09-23 在開發版實機截的（模型 gpt-5.4-mini，視窗 1440×868），沒有設計稿、沒有後製修圖。舊版文件的示範截圖已經移除。

05 · AI Worlds

一句話生成的小遊戲

標題選單的 AI Worlds 是另一條路：一句話讓模型寫出一個 HTML／JavaScript 小遊戲，在 sandbox 裡跑（Rule 12），可以再用一句話修改、存成版本、串成旅程。它和故事章節分開：章節在大地上玩，AI Worlds 是獨立的小遊戲。

02 · Acceptance

每階段只解決一個問題

先證明生成方式，再固定執行契約；避免一開始把新的框架做成另一個龐大引擎。

PHASE 1

AI 能否直接產出不同玩法？

用圖文分支、卡牌交換、場景推理三個題目建立可丟棄原型。共同契約保持最小；記錄生成與局部修改的實際結果。

交付可執行實驗、原始紀錄、契約建議與下一步結論。不把實驗直接當正式 runtime。
PHASE 2

作品能否可靠地執行與保存？

落實作品載入、生命周期、素材與存檔；決定隔離機制、訊息邊界、依賴與資源限制。新舊作品格式明確分流。

交付最小 app 入口；確認一個作品失敗不破壞宿主與其他作品，退出重開仍能讀取進度。
PHASE 3

修改是否比重做便宜？

沿用可用模型連線，加入草稿生成、預覽、定位錯誤與有限修補。修改採相符版本基底，不覆蓋晚到結果。

交付真實生成與規則／素材／布局修改，展示差異、回復與成本紀錄，不擴充發布平台。

03 · Execution & repair

可執行程式的驗證方式（已實作）

OpenUI parser 仍服務既有 DSL 卡帶；新作品走的是隔離執行、訊息驗證與行為檢查這一條，以下都已落地並實測。

執行邊界 · 已實作並實測

  • 每個 session 一個隨機 ulwork:// 主機，由主行程供頁，帶自己的 nonce CSP；sandbox iframe 不給 same-origin。
  • 實測擋下：preload／Node／父頁 DOM／localStorage／eval／fetch／WebSocket／外部圖片／彈窗／自行導頁。
  • 訊息只認這個 session 的視窗、不透明來源、token、schema、大小與頻率；其餘丟棄並計數。
  • 心跳斷了 4 秒就終止那一個行程；實測 97% CPU 的無窮迴圈不影響宿主與其他作品。
  • 已記錄的殘留風險：WebRTC 無法用 CSP 擋（作品身上沒有任何秘密可外流）。

生成閉環 · 已實作並實測

  • 候選先在真的播放器裡跑：要開得起來、要畫出東西、被重放的按鍵與點擊打過一輪不出錯。
  • 再從它自己存的檔重開一次；很多世界的存檔根本還原不了，這一關會抓到並送去修補。
  • 錯誤帶著 main.js:行:列 回給模型，最多修補 2 次；超過就保留錯誤，不動可玩版本。
  • 只有基底仍是目前版本時才接受結果（compare-and-set）；取消與晚到的結果都進不了。
  • 保存版本是不可變的；遊玩進度釘住當時那一版，新版本另開一局，不偷偷遷移。
成本取捨：只建立能幫助生成、執行、修改或修補的機制。不先做通用插件生態、萬用遊戲語言或完整資產流水線。

05 · Story → map

玩家寫故事，地圖長出章節

RPG 是外框，小遊戲是劇情。故事先變成一串章節，散在同一張無限地圖上；章節用完了，大地接著寫，道具跟著人走。

誰負責內容存在哪裡
模型世界聖經（core／style）＋ 3–6 個章節：標題、地點、玩法種類、一段簡述章節計畫寫進卡帶 bible/story.json，和內容雜湊綁在一起
宿主把每章放到地圖上的一個區塊（卡帶章節在向日葵螺旋上；續寫的章節從上一章再走約 2.5 個區塊、每章轉一個黃金角）、畫門、指南針、鎖與解鎖順序純函式，位置不由模型決定
續寫卡帶章節都過完後，大地一次寫一章（一個 @@episode），延續世界聖經與前面的劇情，最多 99 章存檔的 land.storyMore，屬於這個存檔，不是卡帶
章節內容模型寫這章的人和他們說的話、寶物、怪物（Chapter 語言，不寫座標）；攀爬或迷宮類的章節寫成地點。只預寫下一章存檔的 land.episodes[id].stage；宿主擺位置、記錄做了什麼、判定完成
攜帶物每章找到的東西由宿主合併進攜帶物（後面的章節蓋不掉前面的），再帶進下一章存檔的 land.storyCarry；過關同時寫一筆見證 karma
為什麼章節不預先全部生成：玩家可能永遠走不到第五章，先生成就是先付錢。現在的做法是只預寫「下一章」：每過完一章就在背景寫好，走到門口時這章的人和東西已經在那裡；一次只做一件，失敗就停下來等玩家按重試，不會自己一直燒 token。

01 · Why a chain at all

只把「誰先寫下」與「誰看過」放上鏈

遊戲本身不需要鏈。上鏈要解的是兩件離線做不到的事：不可否認的出處，以及任何人都能讀到、不被單一伺服器刪掉的見證。

上鏈的

不可變版本的 sha256 內容雜湊、作者位址、血緣（remix 自哪一版）、可取得檔案的 URI，以及玩家對某一版留下的短見證。

不上鏈的

作品檔案、素材、存檔、故事章節進度、模型輸出與任何個人資料。鏈上沒有內容，只有指向內容的雜湊。

可以完全不用

沒設定 RPC 與合約位址時，生成、試玩、修改、保存版本全部照常；沒設定時不顯示出處區塊，不擋任何流程。

為什麼這個形狀：app 早就用 sha256 內容雜湊當版本身分（卡帶與作品都是），所以鏈上不必重新定義識別碼；下載者自己重算雜湊比對，就能判斷手上的檔案是不是鏈上那一版。

02 · UnwrittenLedger

兩本帳：事實與見證

對應 plan.md 的雙帳本精神：不可變的事實帳，加上可互相矛盾、永不調和的人話帳。合約原始碼在 contracts/src/UnwrittenLedger.sol。

介面做什麼規則
publish(contentHash, parent, kind, uri)事實帳：記下某個不可變版本由誰發布、remix 自哪一版、去哪裡拿檔案同一個雜湊只能發布一次；parent 必須是已發布的雜湊或 0；空雜湊被拒絕
witness(contentHash, note)見證帳：玩家對看過的版本留下 280 bytes（UTF-8）以內的話；app 也照 bytes 截斷只能掛在已發布的雜湊上；任何人都能留；不覆寫、不調和、不排序
revisionOf(hash) / isPublished(hash)讀出作者、血緣、時間、種類與 URI純讀取，不需要金鑰
事件 Published / Witnessed索引用：依雜湊、作者、血緣查詢Published 三個、Witnessed 兩個 indexed 欄位，方便之後做分享頁或排行
刻意沒做：代幣、版稅、拍賣、治理、把存檔或素材寫上鏈。這些都能之後加在同一個雜湊身分上，但不是核心閉環的前置條件。

03 · App integration

金鑰留在主行程，畫面只看得到結果

與模型金鑰同一條規則（CLAUDE.md Rule 6）：renderer 永遠拿不到 RPC URL 與私鑰，只能請主行程去查或去送。

設定（.env）開啟什麼沒設定時
UNWRITTEN_RPC_URL + UNWRITTEN_LEDGER_ADDRESS讀出處：作品列表顯示「on chain · 作者」或「not on chain」不顯示出處區塊，回傳 ledger-not-configured 並附上怎麼設定
再加 UNWRITTEN_PRIVATE_KEY寫出處：保存版本後可按「Register on chain」；主行程簽章送出只讀模式，按鈕不出現，錯誤碼 ledger-read-only
UNWRITTEN_CHAIN_ID選鏈；已知鏈會算出 explorer 位址，但畫面目前只顯示交易雜湊當作本地鏈，沒有 explorer 連結
部署由人來做：bun run contracts:build 編譯並更新已提交的 artifact，bun run contracts:deploy 用你自己的金鑰部署並印出位址。這一步會花 gas，所以不由代理代跑。

04 · ENSv2 names

卡帶有名字：<cartridgeId>.<父名稱>.eth

ENS 已改用 ENSv2。讀取一律經過 Universal Resolver；每個發布的卡帶可以在 Sepolia 上認領一個子名稱，名稱只指向「哪一個版本」，內容仍然不上鏈。

讀取走 ENSv2

viem 2.56 內建 Universal Resolver 0xeeee…eeee，不寫死地址。ENSv2 目前只在 Sepolia（預覽版），所以預設查 Sepolia，可切回主網（主網在同一個入口後面仍是 ENSv1）。依 readiness 頁：接受 DNS 名稱、支援 CCIP-Read，位址與文字紀錄分開查。

卡帶子名稱

名稱只帶三筆文字紀錄：unwritten.cartridge、unwritten.version、unwritten.hash（sha256）。畫面只說「幫這一版命名」；寫上鏈的雜湊由主行程從硬碟重讀，不信任畫面傳來的值。子名稱由 .env 的金鑰持有，玩家不需要錢包，也不會過期。

一次性設定

bun run ens:setup <label>：部署這把金鑰的 Permissioned Resolver 與父名稱的 User Registry（Verifiable Factory proxy），再經 ETH Registrar 以 commit → 等 60 秒 → register 註冊 <label>.eth。費用是可免費 mint 的 MockUSDC；gas 由人來出，所以不由代理代跑。

步驟發生什麼沒設定／沒金鑰時
ens:setup <label> --dry-run用 eth_simulateV1 在 Sepolia 上重播每一步，最後建一個測試子名稱，從 Universal Resolver 讀回它的紀錄比對不需要金鑰，不送出任何東西
ens:setup <label>真的註冊父名稱，印出 UNWRITTEN_ENS_PARENT / _REGISTRY / _RESOLVER 三行貼進 .env沒有 UNWRITTEN_PRIVATE_KEY 就停下並說明
標題 → 卡帶：名稱列即時顯示這一版的名稱：尚未認領／指向這個版本／指向其他版本；有金鑰時可「認領」或「把名稱指向這個版本」（兩筆交易，等收據）顯示「這台機器還沒設定 ENS 名稱」，或名稱照讀、標示唯讀
標題 → 卡帶：用 ENS 名稱開啟名稱 → 它指向的確切版本；收藏裡有相同雜湊就直接「開始玩」，沒有就請你匯入 .cartridge 並寫出它必須符合的雜湊任何機器都能讀，不需要金鑰
文件的部署表已經過時：ENS 文件列的 Sepolia 合約（root 0xc960…）不是 Universal Resolver 現在走的那一套；照它註冊，名稱存在但查不到（ResolverNotFound）。實際在用的是 ens_v2_sepolia_20260916（contracts-v2 @ 366de741，root 0x9703…），這版 resolver 的 setText 改吃 DNS 編碼名稱、initialize 改吃授權清單。地址釘在 src/main/chain/ensCalls.ts；設定腳本先比對鏈上的 root，ENS 再重新部署就停下說明，不會寫出沒人查得到的名稱。

做到哪裡，還沒驗到哪裡
