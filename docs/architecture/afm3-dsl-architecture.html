01 · Executive verdict

可行，但要修正兩個核心假設

7.5/ 10
條件式可行

推薦方向：PCC 低頻產生 WorldPlan / RoomGraph；本機 AFM 以兩階段 guided generation 先產 EventPlan、再產 SceneLayout；最後交給現有 serializer、OpenUI parser 與新的幾何／導航驗證器。

不要直接做：把 PCC 當成固定可選的「AFM 3 Cloud Pro」、宣稱本機必然有 100–200+ TPS，或把 OpenJEV 當成會生成事件鏈的模型。這三點目前都沒有足夠公開證據。

高 架構相容性

保留既有 DSL 真相層

typed AST 是更可靠的生成入口，但 canonical OpenUI Lang、現有 parser、limits 與 cartridge hash 仍是最終真相。

中 平台風險

PCC 不是無條件雲端 API

受 OS、Apple Intelligence、網路、每日 quota、entitlement 與發佈資格限制；必須有可見的本機降級路徑。

中高 工程量

驗證器比 Provider 更關鍵

目前已有 parse、引用與資產檢查，但 AABB、可走性與 headless 物理煙霧測試仍需新增。

02 · Evidence audit

研究前提：哪些能用，哪些要改寫

架構只建立在可重現的公開能力上。以下把「官方已證實」、「合理推論」與「應撤回的說法」分開。

已證實

@Generable 使用 constrained sampling。 Apple 明確說 guided generation 會把 Swift type 轉成 schema，並以 constrained sampling 防止 malformed output。這足以作為 typed AST 的結構保證，但不保證引用、拓撲或玩法語意。
Apple · Guided generation

已證實

OS 27 的 PCC 提供 32K context、reasoning、每日使用限制。 On-device 為 4K、離線且無 request limit；PCC 需要網路並應處理 quota 與 availability。
Apple WWDC26 · Private Cloud Compute

已證實

.fmadapter toolkit 停在 26.0.0，且不相容 OS 27+。 因此 AFM3 路線不應依賴 Apple adapter。
Apple · Foundation Models adapter training

需校正

Flash-to-DRAM 是 AFM 3 Core Advanced 的架構敘述，不是所有 AFM 3 Core 的同義詞。 Apple 說完整權重存於 NAND、依 prompt routing，且生成期間會週期性重選 experts；公開文章沒有支援「100–200+ TPS」這個數字。頁面與產品文案不應承諾該吞吐。
Apple ML Research · Third-generation AFM

需校正

OpenJEV 是 NLI cross-encoder／verifier，不是因果事件生成器。 它可比較 premise 與 hypothesis、rerank 候選；Minecraft 範例的 backward chaining 是外部 scaffold。建議把它定位為可選的事件一致性評分器。
OpenJEV model card

合理推論

OpenUI 的緊湊 DSL 思路可直接沿用，但「靠 grammar masking 得到全部收益」不是 OUI-1 文章的結論。 官方文章主張 OpenUI Lang 最多節省 67% tokens，且以 parser 驗證／修復；本 repo 的 GBNF 遮罩目前只對 llama.cpp 生效。
OpenUI · Introducing OUI-1

用語修正：「端側 0ms 網路延遲」應改成「端側路徑沒有網路 RTT」。模型載入、prompt evaluation、sampling、IPC 與驗證仍有可測量延遲。

06 · Native bridge

先用常駐 Swift CLI + NDJSON

第一版不建議直接做 N-API。模型推論與驗證才是主要延遲；stdio 的隔離、可診斷性與打包簡單度更重要。只有 benchmark 證明 bridge overhead 成為 p95 瓶頸，才升級 N-API。

推薦：persistent stdio

  • Electron main 啟動內嵌且已簽章的 Swift helper，一個 app session 一個 process。
  • stdin/stdout 只傳版本化 NDJSON protocol；stderr 只寫人類可讀 log。
  • requestId + seq 支援多請求、串流、去重、abort 與終止事件。
  • helper crash 時所有 inflight request 以 typed error 結束；可做一次有界重啟。

保留：N-API adapter

  • 與 stdio 共用同一個 NativeTransport 介面，不改 provider 或 UI。
  • 只有在量測顯示大量小事件序列化成本不可接受時導入。
  • 代價是 Swift/C++/Node ABI、Electron major version、簽章與 crash domain 綁得更緊。
IPC envelope · TypeScript / Swift 共同 wire contract 
type NativeRequest = {
  v: 1;
  requestId: string;
  method: "capabilities" | "planWorld" | "generateEvents" | "generateLayout" | "cancel";
  payload: unknown;
};

type NativeEvent =
  | { v: 1; requestId: string; seq: number; type: "accepted" }
  | { v: 1; requestId: string; seq: number; type: "partial"; payload: unknown }
  | { v: 1; requestId: string; seq: number; type: "progress"; phase: string }
  | { v: 1; requestId: string; seq: number; type: "result"; payload: unknown }
  | { v: 1; requestId: string; seq: number; type: "error"; error: AppError }
  | { v: 1; requestId: string; seq: number; type: "cancelled" };

interface NativeTransport {
  request(request: NativeRequest, onEvent: (event: NativeEvent) => void): Promise<Result<void>>;
  cancel(requestId: string): Promise<void>;
  close(): Promise<void>;
}

邊界規則：每行大小上限、UTF-8、未知欄位拒絕、單一 terminal event、stdout 不得混入 log、renderer payload 在 main 與 helper 兩側都驗證。

07 · Model routing

Local 與 PCC 的責任切分

切分依據不是「哪個模型比較強」，而是 context、失敗成本與呼叫頻率。世界級決策可等待、可快取；每個房間的物件與事件必須離線可降級。

工作主要路由輸出失敗策略
世界觀整合、長歷史摘要Apple PCCWorldPlan使用已有快取；沒有快取則本機縮小 scope 或明確 error
Room Graph / 關卡拓撲Apple PCC房間、邊、必要能力、終點，不含精細座標quota／offline 時以 local planner 產較小圖；標示 degraded
因果事件鏈AFM LocalEventPlan本機 repair；可選 OpenJEV 對候選做 entailment rerank
物件、座標、光照AFM LocalSceneLayoutDraft只重生失敗的 layout，不重跑 PCC
Windows 同等路徑llama.cpp / QwenGBNF-constrained compact AST/DSL同一 validator；provider 差異不穿透 service
快取鍵：worldIntentHash + stateRevision + schemaVersion + providerFamily + planningPolicyVersion。PCC 回傳的是可重用 plan，不是一次性 UI text；任何版本改變都必須顯式失效。

08 · Validation

本地驗證是安全邊界，不是品質加分

所有 provider 都是不可信輸入。驗證應由便宜到昂貴排列，第一個錯誤不立刻停止：收集可修復的一組 issues，再做最多兩輪局部 repair。

1
Schema / parsertyped draft schema、數值範圍、array 上限、OpenUI parse；拒絕未知 component 與多餘欄位。
2
Semantic / causalID 唯一、所有引用存在、event precondition 可被前序 effect 滿足、entry 可達 terminal、kit 與 capability 相容。
3
Asset allowlist只允許已安裝 asset id；核對 role、path、content hash。直接沿用目前 validateAssetRef。
4
AABB / placement物件在 floor bounds 內；spawn、exit、互動半徑有 clearance；使用 sweep-and-prune broad phase 避免 O(n²)。
5
Navigation feasibilityv1 對現有 tile / axis-aligned geometry 先用 occupancy grid + flood fill/A*；抽象成 NavigationValidator，未來任意 mesh 再接 Recast NavMesh。
6
Headless simulation以與 renderer 相同 collider recipe 建 Rapier world，固定 timestep 跑有限 ticks；檢查 spawn 穩定、動態物件 settle、必要路徑未被堵死。
7
Canonicalize / receiptserialize → parse deep-equal；寫入 validation metrics、provider、schema version、request hash 與 content hash，之後才可 persist / render。
NavMesh 的務實取捨：現有 DSL 主要是方格地板、牆與 AABB 平台，第一版直接上 Recast 會增加 WASM／worker／mesh bake 複雜度。先以同等「可達性證明」的格網 validator 上線，當 DSL 支援自由 mesh 後再換實作，介面不變。

09 · Data flow

資料流與時序設計

A · 新世界：PCC 規劃 + 本機生成
#CallerReceiverMessage / invariant
1RendererMain servicegenerateScene(intent, stateRevision)；main 驗證 payload 與 snapshot revision
2RouterPCC provider只在無有效 WorldPlan 且 PCC available / below quota 時呼叫
3PCCMain cache回傳 typed WorldPlan / RoomGraph；先驗證 topology，再以版本化 key 快取
4RouterLocal AFM傳單一 room node + 最小必要 state；先生成 EventPlan
5ValidatorLocal AFM事件 plan 合格後才生成 layout；不合格只 repair event phase
6Local AFMMain以 partial event 串流進度；不可把 partial AST 直接渲染
7MainValidatorAST → OpenUI source → parser → static / navigation / simulation
8MainRenderer只送 done(SceneArtifact) 或 typed error；所有 listener 均有 terminal event
B · 驗證失敗：分階段修復

Validator 將 issue 依 owner 分組：event、layout、serialization。只把失敗 phase、原 draft 與精簡 repair hints 回送相同 provider；最多兩次。若仍失敗，回傳 error，不建立手寫 fallback scene。PCC topology 只有在 topology 自身無法滿足時才重跑。

C · Abort / crash / quota
  • Abort：Renderer → main → helper；helper 回 cancelled，晚到的 seq 被丟棄。
  • Helper crash：main 結束所有 inflight request，回 native-helper-exited；最多自動重啟一次，不自動重送非冪等請求。
  • PCC quota：router 在呼叫前查 availability / quota；使用 cache 或明確降級到 local planner，UI 顯示 degraded reason。
  • State changed：若完成時 stateRevision 已不同，artifact 標為 stale，不落盤，由 caller 決定 rerun。

10 · Delivery plan

分 Gate 導入，不先重寫整條 inference

每一階段都可以獨立判斷是否繼續；PCC、N-API 與 OpenJEV 都不是第一個 milestone 的前置條件。

2026-09-22 實作狀態：Gate 1 的 provider contract、router、NDJSON transport（abort、duplicate id、helper crash）與 receipt 已完成；Gate 2 的 Swift @Generable EventPlan → Layout 垂直切片已在 M2 Pro／macOS 27 真機跑通，並由 AppleLocalSceneProvider、Electron main IPC 與 renderer artifact client 串接。橋接器會驗證前置條件可由前序 effect 滿足，並把互動物件種類一路帶到 layout gate；可重現 eval 同時檢查取消、共享詞彙 drift 與 wire shape，小型三案 corpus 為 3/3 通過既有 artifact acceptance gate。Gate 3 已有 parser → asset → AABB／出口淨空／格網可達 gate。Rapier smoke test、PCC adapter、Windows adapter、artifact persistence policy 和打包仍未開始；PCC 無 entitlement 的實際 request 仍失敗。
GATE 0

可用性 spike

在目標 Apple Silicon + macOS 27 建最小 Swift helper：local typed output、stream、cancel、PCC availability / quota、簽章與打包。建立 30–50 個真實 scene eval cases。

Exit criteria能從 Electron main 往返 typed sample；無未解決的 entitlement／distribution blocker；記錄 cold / warm latency。
GATE 1

Provider contract 與 transport

建立 SceneGenerationService、capability negotiation、stdio transport、error taxonomy 與 request receipt；把現有 OpenAI-compatible client 包成 adapter，不改 UI 行為。

Exit criteria現有 llama.cpp / OpenAI tests 透過新介面仍通過；abort、duplicate id、helper crash 有測試。
GATE 2

AFM local：EventPlan → Layout

新增 Swift @Generable schemas、AST serializer 與 round-trip tests；以同一批 corpus 比較 direct DSL 與 typed AST。

Exit criteria成功回傳的 value 100% 通過 schema；最終 semantic pass rate 達產品門檻；session failure 皆為 typed error。
GATE 3

Geometry / navigation / simulation

先做 AABB + grid reachability；把 collider recipe 提取成 shared pure data，再在 worker / main 跑固定 timestep Rapier smoke test。

Exit criteria測試 fixture 能抓到堵門、重疊、越界、不可達與不穩定 dynamic body；validator deterministic。
GATE 4

PCC world planner

新增 WorldPlan / RoomGraph、cache 與降級政策。PCC 只處理 macro topology；用 chaos tests 模擬 offline、quota reached 與 stale cache。

Exit criteria沒有 PCC 也能完成受限生成或給明確錯誤；PCC 不出現在每房／每 chunk 必經路徑。
GATE 5

Windows parity 與可選 verifier

llama.cpp/Qwen 實作相同 AST contract；若 eval 顯示因果錯誤仍高，再實驗 OpenJEV rerank。最後才評估 N-API。

Exit criteria同一 golden corpus、同一 validation report、provider 可互換；任何新增模型都必須有統計收益。
建議量測：first-pass parse rate、semantic pass rate、repair 次數、P50/P95 cold/warm latency、prompt/output tokens、peak RSS、abort latency、PCC fallback rate、validator 各 stage 耗時。不要用單一 TPS 決定架構。

11 · Implemented mechanism map

目前實際運行的生成路徑

這一節是程式碼對照圖，不是另一套設計。它描述目前 Apple local 場景生成如何穿越 renderer、Electron、Swift 與 acceptance gate；舊有 chat inference 不在這條路徑上。

01 · REQUESTRenderer 只送 intent + scene source
02 · TRUSTMain 以 Zod + OpenUI 重解析
03 · CAUSESwift 先產 EventPlan
04 · PLACE同一 plan 產 SceneLayout
05 · ACCEPTArtifact gate 後才回 UI

主路徑：一份 request、一個 validated artifact

  1. renderer/narrative/sceneGeneration.ts 先訂閱 event，再呼叫 window.seed.inference.generateScene()；renderer 送的是 currentSceneSource，不是可被偽造的 SceneGraph。
  2. sceneGenerationIpc.ts 在 main 以 Zod 限制大小、欄位與 enum，並以既有 parseScene() 重建 graph。
  3. SceneArtifactService 選擇可用 provider。現在掛載的是 AppleLocalSceneProvider；非 macOS 或 native helper 不可用時，回傳 typed unavailable error。
  4. Apple provider 對同一 state snapshot 依序呼叫 generateEvents 與 generateLayout；layout 不得修改已驗證的 event plan，也不得漏掉 interact subject。
  5. 只有完成 canonical OpenUI round-trip、資產／幾何／導航檢查的 SceneArtifact 才會經 inference:scene-generate 回傳。

Swift helper：長駐、版本化、可取消

  1. Electron boot 在 macOS 建立 managed Apple provider；app quit 會關閉 helper。helper 路徑由 app bundle / development path 決定，不由 renderer 輸入。
  2. NativeTransport 使用一行一筆的 versioned NDJSON。stdout 僅承載 protocol；診斷只寫 stderr。
  3. 每個 native request 有唯一 ID、單一 terminal event；duplicate ID、helper crash、malformed / out-of-order output 都會被隔離成 typed failure。
  4. Abort 從 renderer 的 AbortSignal 經 main controller 送至 helper cancel request；UI 一定收到 completed、error 或 cancelled 其中之一。
  5. @Generable 只保證 typed generation shape；Swift 仍檢查 payload keys、causal prerequisites、subject requirements 與 layout vocabulary。

12 · Grilled decisions

壓力測試後的決策紀錄

以下是最容易讓方案在第二階段返工的隱藏假設，已直接寫回設計。

Parser 永遠在 typed AST 之後

@Generable 不取代現有 parser。它解決形狀，不解決跨欄位、拓撲、資產與玩法語意。

PCC 不承諾固定 AFM 3 Cloud / Pro 型號

第三方公開入口是 OS-managed model；receipt 記錄 capability 與 route，不虛構不可見的 model ID。

Partial AST 不進 renderer

串流只用於進度與 preview metadata。未完成物件可能缺欄位、缺引用或之後被 repair，不能進物理世界。

事件與空間分兩次 constrained generation

只靠 struct property order 不足以隔離錯誤。先驗證 EventPlan，再把它當 immutable input 生成 layout。

OpenJEV 是 optional judge

只有當 deterministic rules 無法辨別「語意合理性」，且 eval 證明 rerank 有收益時才加入；不能成為 correctness gate 的唯一來源。

stdio 是決策，不是永遠的承諾

以 transport abstraction 保留 N-API；先量測序列化與 context switch，再決定是否承擔 native addon 維護成本。

持久化只接受 validated artifact

draft、partial、repair candidate 與 stale result 都不得寫進 cartridge / instance；這延續現有 immutable revision 規則。

現在就能批准的部分

  • Universal provider contract
  • Swift stdio helper spike
  • EventPlan / SceneLayout 分階段 AST
  • 現有 parser / serializer / asset validation 保留
  • 驗證器介面與 golden corpus

要等 Gate 0/2 數據再批准

  • PCC 作為預設 world planner
  • 具體 latency / TPS 產品承諾
  • N-API 取代 stdio
  • OpenJEV 常駐或 rerank
  • Recast NavMesh 取代 grid validator
